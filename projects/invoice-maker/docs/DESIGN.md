# 設計

## 企画（PdM）
- コンセプト: 登録不要・オフライン・データがブラウザから出ない、インボイス対応の請求書メーカー
- ターゲット: フリーランス・個人事業主・小規模事業者
- サイト形態: **W1**（サーバー処理が不要。静的ホスティングで動く）
- 収益化仮説（保証なし）: 無料公開＋寄付／将来の買い切り有料版（テンプレート・複数ロゴ等）
- スコア: 需要4 / 実装難易度4 / 法的リスク4 / 差別化3 / 運用コスト5 = **20/25**
- 却下: ふるさと納税上限額シミュレーター（需要4・難易度4・法務4・差別化2・運用5=19。既存サービスが飽和、
  2026年10月改正の一次情報の整理に追加コストがかかるため次点としてバックログ）
- 根拠: 2026年10月1日から経過措置の控除割合が80%→70%（令和8年度税制改正後。民間解説サイトによる情報で、国税庁一次資料は未確認）、
  2割特例は2026年9月30日が属する課税期間まで、など制度が動いており関心が高い。
- MVP含む: 発行者情報、明細(10%/8%)、税抜/税込入力、端数処理選択、税率ごとの内訳、印刷/PDF、CSV、JSON、保存一覧、PWA
- MVP含まない: 非課税/不課税、値引き行、PDFの直接生成、ロゴ画像、有料版・ライセンス認証、他言語

## 画面
単一ページ。左: 入力フォーム（発行者／請求内容／明細）、右: 請求書プレビュー。印刷時はプレビューのみ。

## 計算仕様
- 明細金額 = 数量×単価（円未満は選択した端数処理）
- 税率ごとに明細金額を合計し、消費税額の端数処理は **請求書1枚につき税率ごとに1回**
- 税抜入力: 税額 = 合計×税率。税込入力: 税額 = 合計×税率/(100+税率)
- 整数演算で端数処理（浮動小数点誤差回避）

## データモデル
`AppState { issuer, invoice, saved[] }`（`src/storage.ts`）。JSONは `format: "invoice-maker"`, `version: 1`。
