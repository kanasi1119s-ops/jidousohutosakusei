# 設計書: 適格請求書メーカー

## 企画（PdM）
- コンセプト: 登録不要・オフライン・データがブラウザから出ない、個人事業主向けのインボイス対応請求書作成サイト
- ターゲット: 個人事業主・フリーランス・小規模事業者（既存SaaSのアカウント登録や月額課金を避けたい層）
- サイト形態: **W1**（計算・文書生成・ローカル保存のみで完結し、サーバーが本質的に不要なため）
- 市場背景（2026年10月時点の調査）: インボイス制度の経過措置が令和8年度税制改正で見直され、2026年10月から未登録事業者からの仕入税額控除の割合が80%→70%に（7・5・3割控除）。制度への関心が継続。
  既存サービスは Misoca（無料プランは月10通まで）、freee、Square請求書等のクラウド型が中心で、登録不要・ローカル完結型は少ない。
- 収益化仮説（保証ではなく仮説）: 無料版＋寄付／広告なし。将来は買い切り有料版（テンプレート複数・ロゴ挿入・複数発行者）をBOOTH等で提供する案。
  ライセンスはサーバー不要の署名付きキー方式を想定（秘密鍵は人間が生成・保管）。今回は未実装。

### 却下案
- ふるさと納税上限額シミュレーター（約16点）: 既存の年収の壁シミュレーターと収益導線が重複、控除計算の正確性リスクが高い。バックログ保持。

## MVPスコープ
含む: 発行者情報、請求先・基本情報、明細（10%/8%/非課税、税抜/税込）、端数処理選択、源泉徴収、保存・開く・削除、CSV、JSONバックアップ/復元、印刷（PDF保存）、PWA
含まない: 見積書・納品書・領収書、ロゴ画像、複数テンプレート、電子帳簿保存法対応（タイムスタンプ等）、有料版・ライセンス認証、自動PDF生成

## 画面
単一ページ。左: 入力フォーム（発行者／基本情報／明細／計算設定／保存・出力）、右: 請求書プレビュー。スマホ幅は縦積み。

## データモデル（localStorage: `invoice-maker:data:v1`）
```
AppData { version: 1, issuer: Issuer, invoices: Invoice[] }
Issuer  { name, address, registrationNumber, contact, bank }
Invoice { id, number, issueDate, dueDate, customerName, subject, notes,
          items: LineItem[], priceMode: exclusive|inclusive, rounding: floor|round|ceil,
          withholding: boolean, updatedAt }
LineItem { name, quantity, unitPrice, taxRate: 10|8|0 }
```
読み込み時（localStorage/インポート）は `sanitizeAppData` で型・長さ・税率を検証・正規化する。

## 計算仕様（src/calc.ts）
- 明細金額 = 数量 × 単価（選択した端数処理で1円単位に）
- 税抜入力: 税率ごとの合計 × 税率 を端数処理（税率ごとに1回）。税込入力: 合計 × 税率/(100+税率) を端数処理して内税額を算出
- 源泉徴収: 税抜合計 ≤ 100万円: ×10.21%（1円未満切り捨て）、超過: 102,100円 + 超過分×20.42%
  ※ 請求書上で消費税額が区分表示されている場合は税抜金額が源泉徴収の対象。全明細が対象という前提（一部のみ対象の明細指定は未対応）
- 浮動小数点誤差は `toFixed(6)` で丸めてから端数処理
