# 設計

## 企画（PdM）
- コンセプト: 「登録不要・オフライン・データがブラウザから出ない」適格請求書対応の請求書メーカー
- ターゲット: フリーランス・個人事業主・小規模事業者
- サイト形態: **W1**（計算・書類生成のみで、サーバー側処理は本質的に不要）
- 収益化仮説（未検証）: 広告なしの無料版＋買い切り有料版（複数の発行者プロファイル、テンプレート追加等）、寄付。有料版の実装は今回は対象外
- スコア: 需要4 / 実装難易度4 / 法的リスクの低さ4 / 差別化3 / 運用コスト5 = **20/25**
  - 差別化は「登録不要・オフライン」のみで、freee等の大手無料プランとの機能差は小さいため3点
- MVPに含む: 明細入力、税率別（10%/8%/非課税）集計、税込/税抜入力、端数処理（切捨/四捨五入/切上）、
  印刷/PDF保存、CSV出力、保存・読込・削除、JSONバックアップ/復元、PWA
- 含まない: 源泉徴収税の計算、見積書/納品書、電子署名・タイムスタンプ、PDF直接生成ライブラリ、有料版/ライセンス認証、請求書の送信

## 画面
単一ページ。左: 入力フォーム＋保存済み一覧、右: プレビュー（印刷時はプレビューのみ出力）。

## データモデル（`src/calc.ts`）
Invoice { id, number, issueDate, deliveryDate, dueDate, seller{name, registrationNumber, address, contact}, clientName,
items[{description, quantity, unitPriceYen, taxRate(10|8|0)}], priceMode(exclusive|inclusive), rounding, bankInfo, note }

## 計算ルール
- 行金額 = 数量 × 単価（数量は1e6倍の整数で扱い浮動小数点誤差を回避）→ 選択した端数処理で円に丸める
- 消費税額は **税率ごとに請求書1枚につき1回** 端数処理（税抜: 対象額×税率、税込: 対象額×税率/(100+税率)）
- 登録番号は「T＋数字13桁」の形式のみ検証（国税庁の公表サイトでの実在確認はしない）

## セキュリティ設計
DOMはすべて `createElement` / `textContent` で構築（`innerHTML` 不使用）。CSPで外部通信遮断。
インポートJSONは `sanitizeData` で型・長さを検証。CSVは式インジェクション対策（先頭の `= + - @` を無効化）。
