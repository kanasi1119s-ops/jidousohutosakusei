# 設計（invoice-maker）

## コンセプト
「登録不要・オフライン・データがブラウザから出ない」インボイス対応の請求書メーカー。ターゲット: 請求書を月数件発行するフリーランス・個人事業主・小規模事業者。

## サイト形態: W1（静的サイト）
サーバー処理が不要（計算・保存・出力すべてブラウザ内）なため W1。GitHub Pages / Cloudflare Pages 等の無料静的ホスティングで動作。

## スコアリング（25点満点）
| 観点 | 点 | 根拠 |
|---|---|---|
| 需要 | 4 | インボイス制度の経過措置見直し（2割特例の終了→個人事業者向け3割特例、仕入税額控除の経過措置の縮小）が2026年に話題。請求書作成の検索需要は継続的 |
| 実装難易度 | 4 | 計算・保存・印刷のみ。PDFはブラウザ印刷機能を利用し依存ゼロ |
| 法的リスクの低さ | 4 | 第三者データ・スクレイピングなし。税務表示は免責と一次情報誘導で対応 |
| 差別化 | 3 | 既存SaaSは多数。「登録不要・オフライン・データ非送信・買い切り/無料」を軸にする |
| 運用コストの低さ | 5 | 静的ホスティングのみ |
| **合計** | **20** | 18点以上のため採用 |

却下案: ふるさと納税上限額シミュレーター（先行プロジェクトと収益導線が近くスコア再計算が必要）、議事録整形（ブラウザ内AIで難易度が高く複数サイクル前提）。

## 画面
単一ページ: 発行者情報 / 請求書の内容（明細表） / 出力・保存 / 保存済み一覧 / バックアップ / プレビュー（A4印刷対象）。

## 計算仕様（src/calc.ts）
- 明細は税抜単価で入力。明細金額 = 数量×単価 を端数処理。
- 税率ごとの対価の合計に対し消費税額を1請求書あたり税率ごとに1回だけ端数処理（適格請求書の要件）。
- 源泉徴収: 税抜合計 ≤100万円 は ×10.21%、超える部分は ×20.42%（+102,100円）、1円未満切り捨て。
- 数値入力は全角数字・カンマ・円記号を許容。絶対値1e12超や解釈不能な値は無効として直前の値を維持。

## データモデル（src/model.ts）
`AppData { version, issuer, draft, invoices[] }`。インポート時は全フィールドを検証・サニタイズ（型・長さ・列挙値）。

## 非機能
- CSP: `default-src 'self'` ＋ `connect-src 'self'`。DOM は textContent/createElement のみ（innerHTML 不使用）。
- 文字コード: 全て UTF-8(LF)。CSVは BOM 付き、ダウンロード名は英数字のみ。
