# 設計

## プロジェクト選定（PdM）
- 名称: インボイス請求書メーカー / サイト形態: **W1**（サーバー不要。入力データがブラウザから出ない）
- ターゲット: フリーランス・個人事業主・小規模事業者
- 差別化: 登録不要・オフライン・データ外部送信なし。既存の請求書SaaSは会員登録・クラウド保存が前提
- スコア: 需要4 / 実装難易度4 / 法的リスク4 / 差別化3 / 運用コスト5 = **20/25**（採用）
- 却下: ふるさと納税シミュレーター 17/25（既存の年収の壁サイトと収益導線が重複、差別化が弱い）、NISAシミュレーター 17/25（競合多数で差別化が弱い）
- 収益化仮説（保証ではない）: 広告なし無料版＋将来の買い切り有料版（複数テンプレート・取引先台帳）、寄付。未実装

## MVPスコープ
含む: 請求書1枚の作成、10%/8%、端数処理選択、必須項目警告、印刷/PDF、CSV、JSONバックアップ、保存一覧、PWA
含まない: 見積書/領収書、取引先台帳、ロゴ・印影画像、源泉徴収税、電子インボイス(Peppol)、有料版/ライセンス認証

## 画面
1画面（左: 入力フォーム・出力ボタン・保存一覧 / 右: プレビューと警告）。スマホ幅は縦積み。

## データモデル（`src/model.ts`）
Invoice { invoiceNumber, issueDate, dueDate, issuerName, issuerRegNo, issuerAddress, clientName, items[{description, quantity, unitPriceYen, taxRate(10|8)}], rounding, note, bankInfo }
Backup { schema: 'invoice-maker/v1', current, saved[] }。読み込み時は全項目をsanitizeして型を強制。

## 計算（`src/calc.ts`）
明細金額 = 数量×単価（税抜）を端数処理 → 税率ごとに小計 → 税額は小計×税率を1回だけ端数処理。数値は絶対値1兆まで。
