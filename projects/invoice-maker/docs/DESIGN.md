# 設計

## 企画（PdM）
- 1行コンセプト: 登録不要・オフラインで使える、インボイス対応の請求書メーカー。
- ターゲット: フリーランス・個人事業主・小規模事業者。
- サイト形態: **W1**（サーバー不要。データを預けたくないニーズに合致。運用コスト最小）。
- 市場メモ（2026-11 時点の解説記事ベース）: 2割特例は2026年9月30日を含む課税期間で終了し、個人事業者向けに2027〜2028年分の3割特例が設けられたと報じられている。インボイス対応請求書の需要は継続。詳細・適用要件は国税庁の一次情報で要確認。
- 収益化仮説（保証ではない）: 広告なしの無料版＋将来の買い切り有料版（複数テンプレート・PDF直接出力・取引先台帳）／寄付。

### スコア（25点満点）
需要4 / 実装難易度4 / 法的リスクの低さ4 / 差別化3 / 運用コストの低さ5 = **20/25**（採用）

### 却下・見送り
- ふるさと納税上限額シミュレーター: 前回の年収の壁シミュレーターと導線が近く、差別化が弱い（16/25）→ バックログ。
- 議事録整形（ブラウザ内AI）: 実装難易度が高く1サイクルで品質を担保できない（15/25）→ バックログ。

## MVPスコープ
含む: 発行者/請求先/明細（税率別）/端数処理選択/登録番号の形式検証/プレビュー/印刷/CSV/JSON/自動保存/PWA。
含まない: PDF直接生成、複数請求書の管理、取引先台帳、有料版・ライセンス認証、源泉徴収税、税込単価入力、適格返還請求書。

## 画面
単一ページ: 発行者 / 請求内容+明細 / 保存・書き出し / プレビュー（印刷対象）。

## データモデル
`Invoice`（src/model.ts）: 発行者名・住所・登録番号、請求先、請求書番号、取引年月日、支払期限、振込先、備考、端数処理、`items[{name, quantity, unitPriceYen(税抜), taxRate(10|8)}]`。
計算は src/calc.ts（明細金額は円未満四捨五入、税率ごと合計後に1回端数処理）。
