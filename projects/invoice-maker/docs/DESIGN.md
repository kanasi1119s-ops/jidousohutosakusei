# 設計（invoice-maker）

## 企画・スコアリング（PdM）
- コンセプト: 「登録不要・オフラインで使える、適格請求書の作成ツール」
- ターゲット: フリーランス・個人事業主・小規模事業者
- サイト形態: **W1**（計算・文書生成のみでサーバー不要。データはブラウザ内に留められる）
- スコア: 需要4 / 実装難易度4 / 法的リスク4 / 差別化3 / 運用コスト5 = **20/25**（18点以上で採用）
- 根拠: インボイス制度は2026年10月に経過措置が変わる（免税事業者等からの仕入税額控除80%→70%、2割特例の終了、2027年以降の3割特例など。いずれも民間解説による情報で、**国税庁の一次情報での確認が必要**）ため、請求書まわりの関心が継続すると仮説。ただし請求書作成ツールは競合が多く、差別化は「登録不要・クラウドに預けない・オフライン」に限られる。
- 収益化仮説（保証ではない）: 無料公開＋寄付/スポンサー、将来的に買い切りの有料版（取引先マスタ・テンプレート・複数ロゴ等。署名付きライセンスキー方式）。
- 却下案: ふるさと納税シミュレーター（競合が強く差別化が難しい: 17/25）、議事録AI（難易度が高い: 15/25）。

## MVPスコープ
含む: 発行者/宛先/明細入力、税率別集計、必須項目警告、保存/一覧/削除、JSON・CSV入出力、印刷用CSS、PWA。
含まない: PDF直接生成、取引先マスタ、見積書・納品書、電子データ交換(Peppol等)、有料版/ライセンス認証。

## 画面
単一ページ（左: 入力フォーム、右: プレビュー＋保存一覧）。スマホ幅では縦積み。

## データモデル
`Invoice`（`src/calc.ts`）。localStorage キー `invoice-maker:v1`（配列）、`invoice-maker:profile:v1`（発行者情報）。
インポート時は `sanitizeInvoice` で型・範囲を検証し、不正値は既定値へ置換。

## 計算規則
- 明細金額 = 数量×単価（円未満切り捨て、税抜）
- 税率区分ごとの税抜合計に税率を乗じ、1回だけ端数処理（明細ごとの端数処理はしない）
