# 設計書

## コンセプト
フリーランス・個人事業主向けに、インボイス制度に沿った請求書を「登録不要・ブラウザ内完結・オフライン」で作成して PDF 保存できるサイト。

## サイト形態
**W1（静的サイト／ブラウザ完結 PWA）**。サーバー処理は本質的に不要なため W2 は不採用。
スタック: TypeScript + Vite（ランタイム依存パッケージなし）、localStorage、Service Worker。

## プロジェクト選定スコアリング（20/25）
| 観点 | 点 | 根拠 |
|---|---|---|
| 需要 | 4 | 2026/10/1 から経過措置が80%→70%控除へ移行（令和8年度税制改正）。インボイス対応の請求書作成需要が継続 |
| 実装難易度 | 4 | 計算ロジックは明確。PDF は印刷機能に任せ依存ゼロ・日本語フォント問題を回避 |
| 法的リスクの低さ | 4 | 個人情報はブラウザ外へ出ない。税務助言ではない旨を明記 |
| 差別化 | 3 | 既存SaaSが多い。「登録不要・外部送信なし・オフライン」を軸にする |
| 運用コストの低さ | 5 | 静的ホスティングのみ |

採用理由: 上記合計20点（18点以上）。却下: NISA/積立シミュレーター（推定19、次点としてバックログ保持）。

## 収益化仮説（成果は保証しない）
無料公開＋寄付/スポンサー、または買い切りの有料版（取引先マスタ・複数テンプレート）。有料版は署名付きライセンスキー方式を想定（未実装）。

## MVPスコープ
含む: 発行者/請求先/明細入力、税率別集計、端数処理選択、登録番号の形式検証、印刷/PDF、保存一覧、JSON/CSV。
含まない: 源泉徴収税、取引先マスタ、電子署名・タイムスタンプ、国税庁サイトでの登録有無の照会（外部通信ゼロ方針のため）、有料版。

## 計算仕様
- 行金額 = 数量 × 単価。円未満は選択した端数処理で円単位にする（絶対値で処理し符号を戻す）。
- 税抜入力: 税率ごとに行金額を合計 → 税額 = 合計 × 税率 を **1回だけ** 端数処理。
- 税込入力: 税率ごとに税込合計 → 税額 = 合計 × 税率/(100+税率) を1回だけ端数処理。
- 非課税: 税額0。軽減税率(8%)の行は「※」を付し「※は軽減税率対象」と注記。
- 登録番号: 全角/小文字/ハイフンを正規化し `T` + 数字13桁で形式検証（登録の実在確認は行わない）。

## 画面
単一ページ。左（PC幅）/上（スマホ）に入力フォーム、右/下に請求書プレビュー。印刷時はプレビューのみ（A4）。

## データモデル
`AppState { current: Invoice, saved: Invoice[] }`。`Invoice` は発行者・請求先・明細(最大100行)・方式・備考・振込先など（`src/calc.ts`）。
外部から入る値（localStorage/インポート）は `sanitizeInvoice` で型・長さ・列挙値を検証する。
