# 設計ドキュメント: インボイス対応 請求書ジェネレーター

## 1. 企画（PdM）
- **背景**: 2割特例は2026年9月30日を含む課税期間で終了し、2026年10月以降は個人事業者向けの経過措置（報道では「3割特例」）へ移る見込み。フリーランス・小規模事業者が請求書の記載要件・端数処理を改めて確認するニーズがある（Web検索: atsoho.com, Money Forward 等の解説、2026-11-16時点。制度の詳細は国税庁で要確認）。
- **ターゲット**: 登録事業者／免税事業者のフリーランス・個人事業主・小規模事業者。
- **差別化**: 登録不要・データがブラウザの外に出ない・オフライン動作・税率ごと1回の端数処理を仕様として担保。既存の無料ブラウザツールは多数あるため、差別化は中程度。
- **収益化仮説**（今回MVPには含めない）: 無料版を主軸に、将来「取引先マスタ／見積書・領収書への展開／ロゴ・押印画像」等の買い切り有料版や寄付。
- **サイト形態**: **W1**（計算・保存・出力が全てブラウザで完結。サーバー不要）。

### スコアリング（採用ライン18点）
| 観点 | 点 | 備考 |
|---|---|---|
| 需要 | 4 | 制度変更（2割特例終了）に伴う継続的需要。ただし競合も多い |
| 実装難易度 | 4 | 計算・保存・印刷のみで1サイクルでMVP可 |
| 法的リスクの低さ | 4 | 記載要件・端数処理は国税庁ルールに準拠。免責を明記 |
| 差別化 | 3 | 「登録不要・データ非送信・オフライン」中心 |
| 運用コストの低さ | 5 | 静的サイト |
| **合計** | **20/25** | 採用 |

### 却下・見送り案
- **ふるさと納税上限額シミュレーター（見送り）**: 季節需要は高いが、令和8年分の住民税側の控除額（基礎控除・給与所得控除の適用年度）が出典ごとに食い違い、一次情報（国税庁・総務省）にこのセッションから到達できず検証不能。誤った上限額は利用者の寄付額判断に直結するため、法的リスクの観点で見送り。一次情報確認後に再評価。

## 2. スコープ（MVP）
含む: 発行者/請求先/明細の入力、税率別集計、端数処理選択、税抜/税込、源泉徴収、印刷、CSV/JSON、保存一覧、PWA。
含まない: 複数通貨、見積書・領収書、ロゴ/押印、取引先マスタ、PDF直接生成、有料版・ライセンス認証。

## 3. データモデル
`StoreData { version:1, issuer, draft, invoices[] }`、`Invoice { id, number, clientName, issueDate, dueDate, subject, items[], priceMode, rounding, withholding, notes, issuer(スナップショット) }`、`Item { name, quantity, unitPriceYen, taxRate(10|8|0) }`。

## 4. 計算仕様
- 明細金額 = 数量(小数3桁まで) × 単価(整数円) を整数演算で算出し、選択した方式で円未満処理。
- 税率ごとに明細合計 → 消費税を**1回だけ**端数処理（税抜: 合計×税率、税込: 合計×税率/(100+税率)）。
- 源泉徴収: 税抜合計に対し 100万円以下×10.21%、超過分×20.42%（円未満切り捨て）。
- 入力上限: 数量 ±10,000、単価 ±1億円、明細200行（整数が安全域に収まるため）。

## 5. セキュリティ設計
外部通信ゼロ（CSP `default-src 'self'`）、ユーザー入力は `textContent` のみで描画（innerHTML は静的テンプレートのみ）、CSVの数式注入対策、インポートJSONは正規化・上限適用。
