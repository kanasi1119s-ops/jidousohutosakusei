# 設計ドキュメント: 適格請求書ジェネレーター

## 1. 企画（PdM）

- **背景**: インボイス制度の定着に加え、2割特例が2026年9月30日を含む課税期間で終了する旨が複数の解説で報じられており（2026年10月時点のWeb検索による。国税庁の一次情報での再確認は人間が行う）、個人事業主・小規模事業者が請求書の記載要件や税額計算を見直す機会が続いている。
- **ターゲット**: フリーランス・個人事業主・小規模事業者。月数枚の請求書をサクッと作りたい人。
- **差別化**: 登録不要、入力データをブラウザの外に出さない、オフラインでも動く、適格請求書の記載事項を画面上でチェックできる。
- **収益化仮説（検証前の仮説）**: 無料で広告なしを基本とし、将来は「取引先マスタ・テンプレート・見積書/領収書」などを買い切り有料版（署名付きライセンスキー方式）にする余地がある。今回のMVPには含めない。
- **サイト形態**: W1。計算とPDF化（ブラウザの印刷機能）がブラウザ内で完結するため。

### スコアリング（25点満点・採用ライン18点）
| 観点 | 点 | 備考 |
|---|---|---|
| 需要 | 5 | インボイス制度・2割特例終了で請求書関連の関心が継続 |
| 実装難易度 | 4 | 税率別端数処理・源泉徴収・印刷レイアウトに注意が必要 |
| 法的リスクの低さ | 4 | 記載要件は公的に定められており、免責と一次情報確認の喚起で低リスク。税額計算の誤りが主なリスク |
| 差別化 | 3 | 無料の請求書ツールは多い。登録不要・データ非送信・オフラインが軸 |
| 運用コストの低さ | 5 | 静的サイトのみ |
| **合計** | **21** | 採用 |

却下案: 2割特例終了後の税額比較（19点、「3割特例」等の詳細が一次情報で未確認）、ふるさと納税上限（19点、既存無料サイトが多く前回案と収益モデルが重複）。

## 2. MVPスコープ
含む: 請求先・発行者情報、明細（品名・数量・単価・税率）、税抜/税込入力、端数処理選択、税率別集計、適格請求書チェックリスト、源泉徴収、プレビューと印刷PDF、請求書の保存/複製、JSONバックアップ/復元、CSV出力、PWAオフライン、レスポンシブ。
含まない: 見積書・領収書、取引先マスタ、PDFの直接生成、ロゴ・押印画像、複数通貨、電子インボイス（Peppol）、有料版・ライセンス認証。

## 3. データモデル
`src/types.ts` 参照。`AppData { version, defaultIssuer, draft, saved[] }`。請求書は発行者情報のスナップショットを持つ（過去分が後の編集で変わらない）。

## 4. 計算仕様（`src/calc.ts`）
- 行金額 = 数量(小数3位まで) × 単価(小数2位まで)。BigInt の整数演算で行い、1円未満は選択した端数処理（0方向への切捨て／四捨五入／切上げ）。
- 税額は税率ごとに合計して1回だけ端数処理（税抜入力: 合計×税率、税込入力: 合計×税率/(100+税率)）。
- 源泉徴収: 税抜合計に対し、100万円以下は10.21%、超過分は20.42%、1円未満切捨て。
- 未入力(NaN)の行は0円扱い。

## 5. 技術構成
TypeScript + Vite（フレームワークなし）。DOM は `h()` ビルダーで構築し innerHTML を使わない。テストは Vitest と Playwright。PWA は手書きの `public/sw.js`。CSP で外部通信を禁止。
