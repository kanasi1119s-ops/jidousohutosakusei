# 設計書

## プロジェクト選定（Phase 0〜1, 2026-10-02）
- 根拠（Web検索）: 2026年10月にインボイス制度の経過措置が80%→70%へ縮小し、2割特例が終了（個人事業主は3割特例へ移行）。請求書作成の需要が高まる時期。少額特例（税込1万円未満）は2029年9月末まで継続（解説記事: note「インボイスの書き方【2026年版】」、houjinzei-guide.com、jitsumu-guide.com 等。一次情報は国税庁で要確認）。
- 差別化: 既存SaaS（freee/Misoca/INVOY等）は登録・クラウド保存が前提。本ツールは「登録不要・データが端末から出ない・オフライン可」。
- サイト形態: **W1**（サーバー不要。localStorageと印刷CSSで完結）
- スコア: 需要4 / 実装難易度4 / 法的リスク3（税務表現に免責必須）/ 差別化3 / 運用コスト5 = **19/25**（採用）
- 却下案: ふるさと納税シミュレーター（年収の壁と収益モデル重複、18点未満ではないが次回候補）、価格比較スクレイピング（法務リスク）

## MVPスコープ
含む: 発行者/請求先/明細入力、10%・8%混在、税抜/税込、端数処理選択、源泉徴収、登録番号形式チェック、プレビュー、印刷(PDF)、CSV/JSON入出力、自動保存、PWA
含まない: 複数請求書の一覧管理、見積書/領収書、取引先マスタ、PDFライブラリ出力、有料版/ライセンス認証、電子帳簿保存法対応（保存要件は別途）

## 画面
単一ページ。左: 入力フォーム、右: A4請求書プレビュー（印刷時はプレビューのみ）。

## データモデル
`Invoice`（src/model.ts）: 番号・日付・発行者・登録番号・請求先・件名・振込先・備考・金額区分・端数処理・源泉徴収・`items[]`（品名/数量/単価/税率）。JSONは `{schema:"invoice-generator/v1", invoice}`。読み込み時は `sanitizeInvoice` で型・長さ・数値範囲を検証。

## 計算仕様（src/calc.ts）
- 明細金額 = 数量×単価（円未満切り捨て、上限100億円）
- 税抜: 税率ごとの合計 × 税率 を端数処理（1請求書・1税率につき1回）
- 税込: 税率ごとの税込合計 × 税率/(100+税率) を端数処理
- 源泉徴収: 税抜合計 ≤100万円 → ×10.21%、超過分 ×20.42%（円未満切り捨て）
