# 設計書

## 企画（PdM）
- コンセプト: 登録不要・オフライン・データが端末から出ない、インボイス対応の請求書作成サイト
- ターゲット: フリーランス・個人事業主・小規模事業者
- サイト形態: **W1**（サーバー処理が不要。静的ホスティング可）
- 収益化仮説（検証前）: 無料公開＋寄付/スポンサー、将来の買い切り有料機能（取引先/品目のテンプレ複数管理、ロゴ・印影画像など）。ライセンスは署名付きキー方式を想定（未実装）

### スコアリング（20/25）
| 観点 | 点 | 根拠 |
|---|---|---|
| 需要 | 4 | 2026年9月末で2割特例が終了し、個人事業者は2027年分から3割特例へ移行（報道解説）。請求書作成・インボイス対応の関心が継続 |
| 実装難易度 | 4 | 計算は整数演算のみ。PDFは外部ライブラリ不使用（ブラウザ印刷）で日本語フォント問題を回避 |
| 法的リスクの低さ | 4 | スクレイピング・第三者データなし。税務・法務の免責が必要 |
| 差別化 | 3 | 既存の無料ツール・SaaS多数。「登録不要・データ非送信・オフライン」が軸 |
| 運用コスト | 5 | 静的ファイルのみ |
| **合計** | **20** | 採用基準18点以上 |

### 却下・保留
- ふるさと納税上限額シミュレーター（バックログ維持。年収の壁と収益モデルが近く再スコアが必要）
- NISA/積立シミュレーター（バックログ維持）

## 要件（MVP）
含む: 上記「主な機能」。含まない: 見積書/領収書、取引先マスタ、ロゴ画像、PDF直接生成、複数通貨、電子帳簿保存法対応の保存要件（タイムスタンプ等）、サーバー同期。

## 画面
単一ページ: 発行者 → 請求先・内容 → 明細 → 備考 → 操作ボタン → プレビュー → 保存済み一覧/バックアップ。

## データモデル（`src/model.ts`）
`Invoice { id, number, issueDate, dueDate, issuer{name,address,contact,registrationNumber,bank}, clientName, honorific, subject, items[{name,quantity,unitPrice,taxRate}], priceMode, rounding, withholding, notes }`
保存キー `invoice-generator:invoices:v1`。インポート時は `validateInvoice` で検証。

## 計算ルール（`src/calc.ts`）
- 数量は小数第3位まで整数化して計算し浮動小数誤差を回避。1行の金額は端数処理設定に従い円単位へ
- 税率ごとに合計し、消費税は税率ごとに1回だけ端数処理（適格請求書の原則）
- 税込入力時は税込合計から税額＝合計×r/(100+r)で内訳を算出
- 源泉徴収: 税抜合計に対し 100万円以下 10.21%、超過分 20.42%、1円未満切り捨て
- 1行あたり1兆円を超える入力は拒否（精度保護）
