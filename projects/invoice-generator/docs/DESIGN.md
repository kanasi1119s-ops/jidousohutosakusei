# 設計書

## コンセプト / ターゲット
フリーランス・個人事業主・小規模事業者向け。「登録不要・オフライン・データが端末から出ない」請求書作成サイト。

## サイト形態: W1（静的サイト／PWA）
理由: 計算・保存・印刷はすべてブラウザ内で完結し、サーバーが不要。運用コストがほぼゼロ。

## スコアリング（19/25）
| 観点 | 点 | 根拠 |
|---|---|---|
| 需要 | 4 | インボイス制度対応・経過措置の段階縮小（2026年10月〜）で継続的な需要 |
| 実装難易度 | 3 | 計算・検証・保存・印刷でMVPは1サイクルで可能 |
| 法的リスクの低さ | 4 | 第三者データなし。記載事項の誤りリスクは免責と出典で低減 |
| 差別化 | 3 | 無料の登録不要ツールは既存（例: LaunchMyStore）。差別化は記載事項チェック・税率別1回端数処理・バックアップ/CSV・オフライン |
| 運用コストの低さ | 5 | 静的ホスティングのみ |

却下案（同サイクル）: ふるさと納税上限額シミュレーター（既存の年収の壁シミュレーターと収益導線が近く、単独スコア再計算が必要）、NISA積立（金融庁等の公式ツールとの差別化が弱い）。

## MVPスコープ
含む: 上記README機能。含まない: PDF直接生成（ブラウザ印刷を利用）、取引先マスタ、見積書/領収書、電子署名、クラウド同期、有料版。

## データモデル（src/invoice.ts）
Invoice { id, number, issueDate, dueDate, issuer, customerName, items[], priceMode, rounding, note, savedAt }
Item { name, quantity(小数3桁), unit, unitPrice, rate(10|8) }

## 計算仕様
- 明細金額 = 数量×単価（整数演算で端数処理）
- 税率ごとに明細金額を合計 → 税抜入力: 税額 = 合計×税率、税込入力: 税額 = 合計×税率/(100+税率)。いずれも税率ごとに1回だけ端数処理
- 負の単価（値引き行）は絶対値で端数処理し符号を戻す

## 画面
単一ページ: 発行者 / 請求内容（明細） / プレビュー（印刷対象） / 保存済み一覧・バックアップ。
