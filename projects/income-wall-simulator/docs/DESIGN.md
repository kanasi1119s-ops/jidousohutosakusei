# 設計ドキュメント: 年収の壁シミュレーター

## 1. 背景・企画（PdMフェーズ）

- **市場調査サマリ**: 2025〜2026年度税制改正により「103万円の壁」が引き上げられ、2026年10月には
  106万円の壁（月額賃金要件）の撤廃も予定されるなど、パート・アルバイト従事者の年収の壁に関する
  制度が短期間で大きく変化している（Web検索: MONEYIZM, SmartHR Mag., 税理士法人山田&パートナーズ
  各社の解説記事、2026年9月時点）。これに伴い「今年はいくらまで働けるか」を簡単に試算したい
  ニーズが継続的に発生していると判断した。
- **ターゲットユーザー**: 時給制で働くパート・アルバイト従事者、および扶養の範囲内で働くかどうかを
  検討する配偶者・学生。
- **収益化仮説**: 広告非表示・登録不要の無料版を主軸にし、将来的には「複数パターンの比較保存」
  「PDF出力」等を有料機能として追加する余地がある（ただし今サイクルのMVPには含めない）。
- **サイト形態**: **W1（静的サイト／ブラウザ完結）**。サーバー側処理が不要な単純計算ツールであり、
  運用コストの低さを優先した。

### スコアリング（25点満点、採用ライン18点）

| 観点 | 点数 | 備考 |
|---|---|---|
| 需要 | 5 | 2025-2026年の税制改正報道で検索需要が高まっている |
| 実装難易度 | 5 | 計算ロジックのみで完結し、1サイクルでMVPが作れる |
| 法的リスクの低さ | 4 | 計算結果は目安であり、免責事項と一次情報の確認喚起を明記すれば低リスク。ただし制度変更が速いため、しきい値の更新運用は必要 |
| 差別化 | 3 | 既存の壁シミュレーターは多いが、「登録不要・オフライン動作・データ非送信」を明確に訴求する製品は少ない |
| 運用コストの低さ | 4 | 静的サイトのため運用コストはほぼゼロ |
| **合計** | **21/25** | 採用 |

## 2. スコープ（MVP）

### 含む機能
- 時給・週労働時間・月あたり週数・その他年間収入の入力
- 6種類の壁（100/123/106/130/150/201万円）との比較表示、超過/未満の判定
- 各壁までの「週あたり労働時間の上限目安」の算出
- 入力内容の自動保存（localStorage）、JSONエクスポート/インポート
- 試算結果のCSVダウンロード（BOM付きUTF-8）
- PWA対応（オフライン動作）
- レスポンシブ対応（375px〜1280px以上）

### 含まない機能（将来検討）
- 複数パターンの保存・比較
- PDF出力
- 有料版・ライセンスキー認証
- 自治体別の住民税非課税ラインの詳細計算（自治体差が大きいため一般的な目安に留める）

## 3. データモデル

```ts
interface SimulatorInput {
  hourlyWageYen: number
  hoursPerWeek: number
  weeksPerMonth: number
  otherAnnualIncomeYen: number
}

interface Threshold {
  id: string
  label: string
  manYen: number
  category: 'tax' | 'social'
  description: string
}
```

しきい値は `src/thresholds.ts` に定義。法改正に追従するため、値・説明文をこのファイルのみ
更新すれば全画面に反映される設計とした。

## 4. 画面構成

1. 入力フォーム（時給・週労働時間・月あたり週数・その他収入）
2. 試算結果サマリ（想定年収・月収）
3. しきい値比較テーブル（壁ごとの金額・区分・超過/未満・週あたり上限目安）
4. 免責事項・データの扱いに関する説明

## 5. 技術構成

- TypeScript + Vite（フレームワークなし、vanilla DOM操作）
- テスト: Vitest（ユニット）、Playwright（E2E、デスクトップ/モバイル2ビューポート）
- PWA: 手書きの `public/sw.js`（キャッシュファースト＋ビルド済みindex.htmlから
  ハッシュ付きアセットを動的に抽出してプリキャッシュ）
- ビルド後の `<script>/<link>` から `crossorigin` 属性を除去するカスタムViteプラグインを追加
  （詳細はデバッグログRound2参照）

## 6. 法務・免責の設計方針

- 画面下部に恒久的な免責事項を表示し、「専門家への確認」を明記
- しきい値の基準日（`AS_OF`）を明示し、`SOURCE_NOTE` で出典の性質（一般公表資料に基づく目安であること）
  を明記
- 個人情報を一切収集しない設計とすることで、プライバシーポリシー上のリスクを最小化
