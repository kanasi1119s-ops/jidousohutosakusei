# 設計書

## 企画（PdM）
- コンセプト: 「登録不要・入力データが端末から出ない」ふるさと納税の上限額シミュレーター
- ターゲット: 会社員・パート等の給与所得者。年末（12月31日決済期限）に向けて上限額を確認したい人
- サイト形態: **W1**（計算のみで完結しサーバー処理が不要なため）
- 収益化仮説（検証前の仮説）: 広告・アフィリエイト（要人間判断）、寄付/スポンサー。保証はしない
- 市場根拠: 年末の駆け込み需要期。2025年10月のポイント付与禁止、2026年10月の自治体募集経費上限の見直し等で関心が高い（Web検索, 2026-11-18。個別記事の正確性は未検証）。既存の上限額ツールは入力をサーバーに送るものが多く、「端末内完結・オフライン」で差別化

### スコアリング
| 観点 | 点 | 理由 |
|---|---|---|
| 需要 | 5 | 年末の季節需要が強い |
| 実装難易度 | 4 | 計算式は定型。控除の細部の正確さが課題 |
| 法的リスクの低さ | 4 | スクレイピング無し。税計算の免責が必要 |
| 差別化 | 3 | 競合は多い。端末内完結・オフラインが軸 |
| 運用コストの低さ | 5 | 静的ホスティングのみ |
| **合計** | **21/25** | 採用 |

却下: インボイス請求書ジェネレーター（PDF出力の実装難易度が高く、季節性が弱いため次回以降）19/25、NISA積立（需要の季節性が弱い）17/25 は不採用。

## MVPスコープ
含む: 給与収入・社保・iDeCo・その他控除・配偶者・扶養（一般/特定）・寄附済み額の入力、上限額と余裕目安(90%)、年収別一覧、JSON/CSV、PWA
含まない: 住宅ローン控除、事業/配当/譲渡所得、2,000万円超、老人扶養・障害者控除、寄附先の提案、決済・ライセンス認証

## 計算モデル
1. 給与所得 = 給与収入 − 給与所得控除（令和7年分以降の区分）
2. 社会保険料: 入力値、無ければ給与収入×15%（概算）
3. 所得税の課税所得 = 給与所得 − (社保+iDeCo+その他) − 基礎控除(令和7・8年分の特例加算込み) − 配偶者38万 − 扶養(一般38万/特定63万)
4. 住民税の課税所得 = 同様に 基礎控除43万・配偶者33万・扶養(一般33万/特定45万)
5. 調整控除 = 人的控除差(基礎5万+配偶者5万+一般5万/特定18万) に応じた額×5%（課税所得200万円超は逓減、最低2,500円）
6. 住民税所得割額 = 課税所得×10% − 調整控除
7. 上限額 = 所得割額×20% ÷ (90% − 所得税率×1.021) + 2,000円
- 配偶者は「給与収入160万円以下」の場合のみ満額控除として扱う簡易化
- 数式や控除額は一次情報での再確認が必要（docs/LEGAL.md）

## 画面
単一ページ: 入力フォーム → 試算結果（上限額・90%目安・残額・内訳）→ 年収別一覧 → 免責。
