# 設計書

## コンセプト
「登録不要・データはブラウザ内だけ・オフラインでも使える」インボイス対応の請求書メーカー。
ターゲット: フリーランス／個人事業主／小規模事業者（月に数枚〜数十枚の請求書を作る人）。

## サイト形態: W1（静的サイト／ブラウザ完結）
サーバー側の処理が本質的に不要（計算・保存・印刷はすべてブラウザ内）なため W1。運用コストはほぼゼロ。

## プロジェクト選定スコア（20/25 ≧ 18）
| 観点 | 点 | 根拠 |
|---|---|---|
| 需要 | 4 | インボイス制度は継続的な検索需要。2026年10月は経過措置（仕入税額控除の割合）・2割特例終了の節目（報道・解説記事で確認、下記） |
| 実装難易度 | 4 | 依存ゼロで1サイクルのMVPが可能（PDFはブラウザの印刷機能を利用） |
| 法的リスクの低さ | 4 | 第三者データ・スクレイピングなし。記載事項は公開情報。税務助言は行わない旨を明記 |
| 差別化 | 3 | 競合はアカウント登録型クラウドか有料買い切り（BOOTH等）。無料・登録不要・端末内完結・オフラインが軸。ただし機能の広さでは既存サービスに劣る |
| 運用コスト | 5 | 静的ホスティングのみ |

却下案: 価格比較スクレイピング系（利用規約確認コスト大・法務リスク）、議事録整形（実装難易度が高く複数サイクル前提）。

## 市場メモ（調査日 2026-10-18、Web検索）
- 2026年度税制改正で、買い手側の仕入税額控除の経過措置が「2026年10月から70%→2028年10月から50%→…」と緩和される内容が報じられている（情報源により記述差あり。最終確認は国税庁）。
- 2割特例は2026年9月末で終了（個人事業主は3割特例への移行が報じられている）。
- 競合: 無料クラウド型は月間発行数の制限や登録が必要なものが中心。登録不要・買い切り・オフライン型は有料（BOOTHの商品が存在）。
  → 本サイトは機能を絞る代わりに無料・登録不要・端末内完結を訴求。

## MVPスコープ
含む: 4種類の書類、税率別集計、税込/税抜、端数処理、保存、CSV、JSONバックアップ、印刷、PWA、検証と警告。
含まない（バックログ）: 源泉徴収税の計算、複数の取引先マスタ、ロゴ・印影画像、PDFの直接生成、有料版・ライセンス認証、多言語。

## 画面
単一ページ。左: 入力（発行者／書類情報／明細／振込先・備考／操作／保存済み一覧）。右: A4プレビュー（印刷時はこれだけを出力）。
スマホ幅では縦積み。

## データモデル（`src/invoice.ts`）
- `Issuer { name, address, contact, registrationNumber }`
- `InvoiceDoc { id, kind, number, issueDate, transactionDate, dueDate, clientName, honorific, subject, items[], priceMode, rounding, bankInfo, notes, updatedAt }`
- `LineItem { name, quantity(小数第2位まで), unitPriceYen(整数), taxRate(10|8) }`
- 保存キー（localStorage）: `invoice-maker-jp:issuer:v1` / `:docs:v1` / `:draft:v1`
- バックアップJSON: `{ app: "invoice-maker-jp", version: 1, issuer, documents[] }`（読み込み時に全項目を検証・丸め込み）

## 計算ルール（`src/calc.ts`）
- すべて整数演算（数量は100倍して扱う）。浮動小数点誤差を避ける。
- 明細金額 = 単価 × 数量 を選択した端数処理で円に丸める。
- 税抜入力: 税率ごとに明細金額を合計 → 合計 × 税率 を1回だけ端数処理。
- 税込入力: 税率ごとの税込合計から内税額 = 合計 × 税率/(100+税率) を1回だけ端数処理。
- 負数（値引き行）は絶対値で丸めて符号を戻す。
- 上限: 数量 ≤ 100,000、|単価| ≤ 100,000,000、|明細金額| ≤ 1兆円（安全な整数範囲内）。

## 文字コード方針
UTF-8(BOMなし)・LF。CSVのみBOM付きUTF-8。ダウンロードファイル名は英数字のみ（`safeFileToken`）。
フォントはシステムフォントのみ（外部フォント不使用）。
